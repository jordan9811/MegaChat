# Flow: a paid seat, from link to leave

The allowance path: the one the join page takes for MetaMask, and for any wallet when the server has no MPP meter. Two of the four payment modes in the code are on it (`passkey_stream` for a funded wallet, `credit_stream` for earned balance). A Privy wallet goes to the MPP channel route instead whenever `/api/config` says `meterMode: 'mpp_session'` (`web/lib/join-page.ts`, `joinSeatMpp`); whether that is a live money path is status call U1, on the internal *Needs a status call* page.

| # | Step | Where | What can stop it |
|---|---|---|---|
| 1 | Viewer opens `/<handle>` or `/join?room=<id>`. The page resolves the room from the path or query (`parseStreamRoomFromUrl`). | `web/lib/join-page.ts` | unknown room → `/api/config` 404 |
| 2 | `GET /api/config?room=…` returns the terms: `passkeyTickPrice`, `passkeyTickSeconds`, `maxSession`, `maxSeats` (the cap in force), `viewerRidesFree`, `joinStream.enabled`, the token, `transport`. | `server.js`, `/api/config` | room paused → `roomActive: false` |
| 3 | Viewer signs in (Privy: Google, email, passkey — or MetaMask) and, if needed, funds the wallet with a plain token transfer. | `web/lib/join-page.ts`, `walletMode`; `web/components/providers/tempo-wallet.tsx` | no wallet → the page offers both paths |
| 4 | First `POST /api/join/passkey` without a payment header fetches session terms for this wallet, including the spender to approve (`payTo`). | `web/lib/join-page.ts` (`const first = await fetch('/api/join/passkey'…)`); `escrowTermsFor`, `server.js` | room with no payout address → 409 `no_payout_address` |
| 5 | Viewer signs **one** `approve(spender, sessionCap)` on the payment token — the seat escrow contract in escrow mode, the seller key in direct mode; the page waits for the transaction. | `web/lib/join-page.ts`, `SEL_APPROVE`, `waitForTx` | rejected in wallet |
| 6 | Second `POST /api/join/passkey` with the `x-modular-payment` header. Server order: whitelist short-circuit (`tryWhitelistJoin`) → `joinStream.enabled` → `checkFeatureGates` (min watch time) → payment authorization → `addParticipant`. Seat exists in `activeSeats` with `paymentMode: 'passkey_stream'`. In escrow mode the cap is deposited into the contract before the seat is confirmed. The response carries the seat id and its `seatToken`, the proof every later step on the seat sends. | `server.js`, `/api/join/passkey`; `escrow-chain.js` | 403 `feature_disabled` / `min_watch_time`; 402 insufficient; 409 no chair; 503 `escrow_deposit_failed` frees the seat (`retry: 'direct'`) |
| 7 | The grant wakes the overlay: under lazy connect it connects to LiveKit now if it was not already awake (`seatOccupied`; `prewarmTrigger` fired on the first Join click). No tile yet — `seat_added` waits for step 9. | `server.js`, `addParticipant`; `livekit-activity.js`; `livekit-lazy.config.js` | breaker blocking new connections → 503 on token |
| 8 | Viewer's browser asks for a publisher token for *this* seat, sending the seat token, and opens a local camera preview; nothing is published yet. | `POST /api/livekit/token`, `server.js`; `livekit.js`; `web/lib/join-page.ts` (`createTracks`) | no matching seat token → 403; camera permission denied → `schedulePendingCameraTimeout` ends the seat |
| 9 | Viewer presses GO LIVE: `camera_ready` with the seat token. The server marks the seat live and broadcasts `seat_added` — the overlay allocates the tile and plays the entry stinger — and records a `seat` moment on the room's airing if one is open. The page publishes camera + mic only on that answer, asking again every 5 s until it has one. | `activateSeatLive`, `server.js`; `goLiveNow`, `askToGoLive`, `web/lib/join-page.ts` | wrong or missing seat token → `seat_refused` |
| 10 | Every second: `tickAllMeters` → `tickPasskeyStreamSeat`. An escrow seat's tick is a ledger row against the cap already in the contract; a direct seat's tick is pulled from the wallet to the room's payout address (`settlement.pull`). The seat's `remaining`/`spent` are broadcast to the viewer. A hidden overlay skips the tick. | `server.js`, `tickAllMeters`, `tickPasskeyStreamSeat`; `seat-escrow.js`, `shouldCharge` | pull fails or cap reached → `removeParticipant(seat, 'out_of_funds')`; the halted money door → `ledger_corrupt` |
| 11 | In LiveKit rooms a network blip pauses ticks client-side and the server allows `LIVEKIT_SEAT_GRACE_S` (+5 s) before a stale kick. | `tickAllMeters`, `server.js` | past grace → `payment_stalled` |
| 12 | Viewer leaves (`POST /api/leave/:seatId`, the seat token in the body; a bare id is 403), closes the tab (WS close → grace timer), is kicked (`/api/dashboard/*` → `removeParticipant`), or runs dry. | `server.js`, `removeParticipant` | — |
| 13 | `removeParticipant`: delete from `activeSeats`; record `seat_leave` on the airing; `lkActivity.seatVacated` starts the overlay's disconnect grace; LiveKit kicks the participant (one that joins after this is removed on its own webhook, `kickOrphanSeat`); `seat_removed` to the overlay (exit stinger); the seat's pending bucket closes; an escrow seat's ledger figures are attested to the contract once (`attestSeatFromLedger`); `refundSeat` — for a direct `passkey_stream` seat nothing to refund, the unspent allowance never left the wallet. | `server.js`, `removeParticipant`, `refundSeat` | none of it blocks removal (`refundSeat` is fire-and-forget) |

## Where the money is at each point

- Before step 5: nowhere. No hold, no deposit.
- After step 5: an **allowance** on the token, capped at the session cap. Still in the viewer's wallet.
- After step 6, escrow mode: the session cap is in the seat escrow contract (`escrow-chain.js`, `deposit`).
- Steps 10 onward: escrow mode, ticks are ledger rows and nothing moves per tick; direct mode, one tick per second leaves the wallet to the room's `payoutAddress`, never the platform wallet (`tickPasskeyStreamSeat`, `server.js`).
- After step 13: direct mode, the pulled ticks are the streamer's and the remainder of the allowance stays where it always was; escrow mode, the contract pays by the attested figures and the unspent cap returns to the viewer when the escrow finalizes (`refundSeat`, `server.js`: "unspent returns from the contract at finalize").
